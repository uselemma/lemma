Connect your app to Lemma and send one complete agent trace. The agent prompt is the recommended path; set up manually when you can’t run `npx`, or you’d rather add tracing yourself. Both paths work in a new organization and in one that’s already set up.

One agent execution is one [trace](/tracing/instrumentation/concepts). It records the model calls, tool calls, retrieval, and app logic of that execution. The software development kit (SDK) sends each trace to the Lemma API.

## Before you start

Both paths need:

- **Role**: owner or admin of your Lemma organization, since only they can approve the agent’s setup or create an API key
- **Repository**: the code of the app that runs your agent, on your machine

The agent prompt also needs:

- **Coding agent**: one that can run commands, such as Claude Code, Cursor, Codex, or OpenCode
- **Node.js 20 or later**: the setup command runs with `npx`, in Python apps too

## Set up with the agent prompt

The prompt contains no key: Lemma creates the keys when you approve. You copy the prompt, paste it into your coding agent, approve in the browser, and let the agent finish.

<Steps>
  <Step title="Copy the prompt">
    In a new organization, the setup modal opens when you first sign in to [Lemma](https://platform.uselemma.ai). Copy the prompt from its **Connect your agent** step, which adds a `Lemma organization:` line naming your organization. If your organization is already set up, copy the prompt from here:

    ```text
    Set up Lemma monitoring for this app.

    Fetch and follow this skill end to end:
    https://raw.githubusercontent.com/uselemma/lemma/main/skills/lemma-setup/SKILL.md
    ```
  </Step>
  <Step title="Paste it into your coding agent">
    Open your coding agent in the app’s repository and paste the prompt. The agent reads the codebase, proposes a project name and an agent name, and asks you two questions before it changes any code:

    - **Approach**: how the app sends traces, through a framework integration, the direct SDK, or next to existing tracing such as Langfuse
    - **Scope**: which agent paths to trace first
  </Step>
  <Step title="Approve in the browser">
    Your browser opens the approval page, and the agent shows you an approval code. If your organization has no plan yet, the page first asks you to choose one in **Choose your plan**. Checkout brings you back to the page.

    Check that the page shows the same code and the organization you mean. To approve in another organization, such as one that already has a plan, choose **Switch organization** below the plans or next to the organization name. It appears only when you belong to another organization.

    When the page labels the organization as the one your agent was set up for, it has no **Switch organization** link. If that organization is wrong, ask the agent to start the approval again without naming one, then switch on the new page.

    Confirm or edit the agent name, pick the project, and approve:

    - **New project**: confirm or edit the project name, then choose **Approve and create project**
    - **An existing project**: pick it under **Project**, which hides the project name field, then choose **Approve**

    The **Project** list appears only when your organization has projects already. The code expires 10 minutes after the agent starts the approval.
  </Step>
  <Step title="Let the agent finish">
    After you approve, the setup command saves the ingest key to `.env` and the admin key to your coding agent’s Model Context Protocol (MCP) config. A key goes to a private file under `~/.lemma/setup/` instead when `.env` or the config can’t take it, or when your coding agent isn’t one that setup configures. The agent gives you the path of each such file:

    - **`LEMMA_API_KEY` and `LEMMA_PROJECT_ID`**: copy them wherever your app loads its environment, then delete the file
    - **The `lemma` MCP entry**: copy it into your coding agent’s MCP config, then delete the file. For Claude Code, add it the way the message says, either with its command or in `~/.claude.json`; both keep it in the project’s local scope. Never paste it into the committed `.mcp.json`

    [Setup command and skill](/reference/setup-command) lists each file and step.

    The agent then adds tracing, and asks before it runs your app to send a first trace. Then it asks you to reload its MCP servers. It proposes [artifact](/platform/artifacts) claims about what your agent is for, and you approve each one.
  </Step>
</Steps>

## Set up manually

Manual setup takes two steps: a project and its key, then the integration.

<Steps>
  <Step title="Get a project and key">
    Where the key comes from depends on your organization:

    - **New organization**: in the setup modal, on **Connect your agent**, choose **Set up manually**. Enter a **Project name** and an **Agent name**, then choose **Create project and key**. **Your project is ready** shows a `.env` block with both values
    - **Organization already set up**: create the project with **Create project** in the project switcher, then choose **Generate API key** under **Get started with Lemma** on its dashboard. You can also create a key under **Developer → API keys** in your organization settings, with the project and the **Ingest** scope; the project ID is the identifier after `/projects/` in the project’s dashboard URL

    Copy the key now: Lemma shows it only once. Add both to the `.env` file your app loads:

    ```bash
    LEMMA_API_KEY=sk_your_api_key_here
    LEMMA_PROJECT_ID=12345678-1234-1234-1234-123456789012
    ```

    An ingest key can only send traces. Keep it server-side: never commit it, and never put it in browser code.

    The process that runs your agent must load `.env`: Next.js loads it, a Node.js script needs `node --env-file=.env`, and Python needs `python-dotenv`.
  </Step>
  <Step title="Add the integration">
    The setup modal shows tabs under the key with the install, client setup, and instrumentation steps for each framework and language. The project’s **Get started with Lemma** screen shows the same tabs under **Install manually instead**. Each integration page has the full setup: [Vercel AI SDK](/integrations/vercel-ai), [OpenAI Agents](/integrations/openai-agents), [LangChain](/integrations/langchain), [LangGraph](/integrations/langgraph), and [Mastra](/integrations/mastra). Without a framework, [Instrument an agent](/tracing/instrumentation/instrument-an-agent) adds the direct SDK one piece at a time.
  </Step>
</Steps>

## Verify a ready trace

A key, an SDK install, or an ingest attempt doesn’t prove that Lemma sees your agent. A **ready** trace from a production-like path does.

Run a production-like request through your agent. In the setup modal, Lemma checks the first trace when it arrives. If a check fails, the modal gives you a prompt to paste into your coding agent, then checks the next trace. Choose **Go to dashboard** when you’re ready. Outside the setup modal, open **[Traces](/platform/traces)** in the [Lemma dashboard](https://platform.uselemma.ai). You should see:

- One trace for the whole agent execution
- A root with input and output you recognize
- The agent’s work nested under the root

If no trace arrives, set `LEMMA_DEBUG=1` and run the agent again; [Debug mode](/tracing/troubleshooting/debug-mode) explains the log. After the trace looks complete, see [Overview](/platform/overview) for issues, Inspect, and workflow connections.

## Before you deploy

Your deployed app reads the same settings from its own environment:

- **Ingest key and project ID**: add `LEMMA_API_KEY` and `LEMMA_PROJECT_ID` to your deployment’s environment variables or secrets
- **Release**: set `LEMMA_RELEASE` to the deployed version, such as the commit SHA, so each trace records it. To read it from a variable your host sets, see [Set the release](/tracing/instrumentation/instrument-an-agent#set-the-release)
