Project webhooks send **signed HTTP POST** requests for **issue lifecycle** events. They are separate from [Slack](/connections/slack) alerts and from [Lemma MCP](/connections/mcp).

Lemma does not emit incident-lifecycle events. Customer alerting follows **issues**. If you still see older incident-named samples, ignore them.

## Events

| Event | When it fires |
|-------|---------------|
| `issue.created` | A new issue was created |
| `issue.resolved` | The issue was marked resolved |
| `issue.dismissed` | The issue was dismissed |
| `issue.reopened` | A resolved issue reopened from matching evidence. Dismissed issues do not reopen this way. |

## Setup

<Steps>
  <Step title="Add a webhook endpoint">
    In the project, go to **Settings → Webhooks** and add an **HTTPS** endpoint. Select the issue events you need.
  </Step>

  <Step title="Save your signing secret">
    After creating the endpoint, Lemma shows your signing secret **once**. Copy it immediately and store it in the receiver's secret manager — you cannot retrieve the stored value again.

    Regenerating a secret **replaces** it. The previous secret stops working.
  </Step>

  <Step title="Verify signatures and freshness">
    Every request includes:

    - `X-Lemma-Signature` — `sha256=<hex>` HMAC-SHA256 of the **exact raw body**
    - `X-Lemma-Timestamp` — validate freshness before processing
    - `X-Lemma-Event` — route on the event type

    <Tabs>
      <Tab title="Node.js">
        ```typescript
        import { createHmac, timingSafeEqual } from "crypto";

        function verifyLemmaSignature(
          rawBody: string,
          secret: string,
          signature: string,
        ): boolean {
          const expected =
            "sha256=" +
            createHmac("sha256", secret).update(rawBody).digest("hex");
          const a = Buffer.from(expected);
          const b = Buffer.from(signature);
          return a.length === b.length && timingSafeEqual(a, b);
        }
        ```
      </Tab>

      <Tab title="Python">
        ```python
        import hmac, hashlib

        def verify_lemma_signature(
            raw_body: bytes,
            secret: str,
            signature: str,
        ) -> bool:
            expected = "sha256=" + hmac.new(
                secret.encode(), raw_body, hashlib.sha256
            ).hexdigest()
            return hmac.compare_digest(expected, signature)
        ```
      </Tab>
    </Tabs>

    <Warning>
      Always use the **raw request body** for signature verification. Parsing and re-serializing the JSON will change whitespace and break the signature check.
    </Warning>
  </Step>
</Steps>

## Payload

All events share a common envelope: `event`, `timestamp`, `projectId`, and an `issue` object (id, status, and related fields). Do not assume an `incident` object.

```json
{
  "event": "issue.created",
  "timestamp": "2025-04-07T12:00:00.000Z",
  "projectId": "39e9c46a-...",
  "issue": {
    "id": "abc123",
    "status": "open",
    "createdAt": "2025-04-07T11:58:00.000Z"
  }
}
```

## Delivery and retries

Lemma treats a `2xx` response within **10 seconds** as success. Failed deliveries retry with exponential backoff.

Delivery history (status and latency, not signing secrets) is in **Settings → Webhooks → Delivery log**.

Offload slow work so you can return `2xx` immediately.

## Testing

Use the test action next to an endpoint to send a synthetic issue-lifecycle payload. Confirm the endpoint is reachable and signature verification works before you rely on real events. Keep the endpoint enabled after a successful test.

## Security checklist

- Verify `X-Lemma-Signature` and `X-Lemma-Timestamp`
- Route on `X-Lemma-Event`
- HTTPS endpoints only
- Store the signing secret in an environment variable, never in source control
- Distinct from Slack alerts and from Linear's inbound webhooks to Lemma
